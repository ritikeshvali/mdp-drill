reinforcement learning

MDP Framing Drill

Build a gut feel for reinforcement learning by learning what a Markov Decision Process is, then practising how to frame real problems as one.

1 · the problem

Why reinforcement learning exists

Some problems have no answer key. In ordinary machine learning you copy labelled examples ("this photo is a cat"). In reinforcement learning (RL) you learn from consequences, by trying things and seeing what pays off. It is built for sequential decisions under uncertainty with delayed reward.

Delayed reward: the payoff for a good decision often arrives many steps later, not right away, so you cannot judge a move by its immediate result. In chess you sacrifice a piece now to win twenty moves later.

2 · the loop

The agent and the environment

Two players pass signals back and forth:

agent the learner we are training, the thing that makes decisions.
environment everything outside the agent that it acts on and that reacts back.

The agent observes a state, picks an action, and the environment answers with a reward and the next state. Repeat until the task ends. That is the whole idea.

3 · the definition

What an MDP is

A Markov Decision Process (MDP) is the formal name for that loop: a five-piece description — states, actions, transitions, rewards, and a discount — that turns a fuzzy goal ("play well") into a problem you can actually solve with math. Almost every RL algorithm is, underneath, solving an MDP.

4 · the "M"

The Markov property

The future depends only on the present state, not the whole history that led there. So the state must be a sufficient summary of the past: once you know it, remembering how you got there adds nothing.

A chess board is Markov — the current position tells you everything the legal moves depend on. Your position alone in a game with a moving ball is not — you would also need the ball's velocity to know what happens next.

5 · the checklist

The 6 things to name, every time

Each has two worked examples. Toggle between a simple one (a robot on a grid reaching its charging dock) and a real one (an app choosing your next Instagram Reel).

statethe complete snapshot the agent uses to decide right now

Precisely: one point in the space of possible situations; it must be a sufficient (Markov) summary of the past.

In the grid game where the robot must reach its dock, the state is the cell it currently occupies. That's all it needs to choose its next move; it doesn't need the path it took.

The app's picture of you at this moment: which reels you just watched fully, which you skipped, what you liked recently, plus features of the reel on screen.

actiona choice the agent makes — what it does, not what happens to it

Precisely: one element of the set of actions available in the current state.

Move up, down, left, or right. A gust of wind shoving the robot is not an action — that's the environment acting.

Which reel to show you next (picked from a shortlist). Your like or skip is not the agent's action — it's your reaction, which becomes reward.

rewardone number the environment returns after each move, saying how good that move's immediate outcome was

Precisely: a scalar (a single number). You maximize its cumulative sum over time, never any one step. It is the only signal of what you want.

+10 for reaching the dock, −1 for every step taken (to push for speed), −100 for falling down the stairs.

+ for watch time and a like or share, − for a fast skip or a "not interested".

transitionthe rule for what happens next — given where you are and what you do, which state do you land in? Often random.

Precisely: P(s′ | s, a), read as "the probability of landing in next state s′, given that you are in state s and take action a".

"Move right" lands you one cell right 90% of the time, but on a slippery floor 10% of the time you slip down. Not knowing these odds in advance is what forces you to learn by trying (model-free RL).

After a reel is shown, which state you move to depends on how you react, which the app can't predict for sure, so it's learned from data.

discount / horizonhow much you value future reward versus immediate, and whether the task ever ends

Precisely: a discount γ between 0 and 1. Return = r₁ + γr₂ + γ²r₃ + … Near 0 = short-sighted; near 1 = far-sighted. Episodic tasks have a natural end (a game); continuing tasks run forever (a thermostat).

At γ = 0.9, a reward 10 steps away is worth about 0.9¹⁰ ≈ 0.35 of the same reward now, so reaching the dock in 3 steps beats reaching it in 30.

A session is an episode. A high γ optimizes for you staying engaged over the whole session, not just the next three seconds — a low γ breeds clickbait.

the trapnot a component — a practice aid

The one mistake an examiner is really probing. Usually it's confusing who the agent is (the agent's action versus the user's or environment's reaction), or proposing a state that isn't actually Markov. The drill flags the specific trap on each scenario.

6 · what you solve for

Policy, return, value

Policy (π) — the agent's strategy: a rule that says, given the state you're in, which action to take. It's the actual "brain" you end up with.

Return — the total reward from now to the end, with later rewards discounted by γ. It's what you truly want to maximize, not the next reward — which is exactly what makes delayed reward tractable.

Value — the expected return if you start in a given state and follow your policy: "how good is it to be here, counting all the future reward I can expect, not just what's in front of me." This is the quantity nearly every RL algorithm is really estimating — get the values right and a good policy falls out (act toward the higher-value states).

Optimal policy — the strategy that achieves the highest expected return from every state. Solving an MDP means finding it.

7 · how they're solved

The beginner algorithm map

Know the rules (the transitions and rewards)? Then you can plan: Value Iteration and Policy Iteration compute the answer directly.

Don't know the rules? Then you learn from experience: Q-learning (off-policy — learns the best policy no matter how it explores) and SARSA (on-policy — learns the policy it actually follows).

Too many states to list in a table? Approximate the value with a neural net → Deep Q-Network (DQN), the bridge to deep RL.
